1. De STATA / SPSS à R : le tableau de correspondance

Vous savez déjà faire tout cela ; seule la syntaxe change.

L’intention STATA SPSS R
Créer une variable generate x = 2+3 COMPUTE x = 2+3. x <- 2 + 3
Garder des lignes keep if age > 15 SELECT IF (age>15). filter(d, age > 15)
Garder des colonnes keep age sexe /KEEP age sexe select(d, age, sexe)
Décrire un fichier describe CODEBOOK str(d)
Résumer summarize DESCRIPTIVES summary(d)
Tri à plat tabulate v FREQUENCIES v. table(d$v)
Trier gsort -pop SORT CASES BY pop (D). arrange(d, desc(pop))

La différence de fond n’est pas la syntaxe. En STATA et en SPSS, un fichier de données est actif à la fois, et les commandes s’y appliquent implicitement. En R, plusieurs objets coexistent en mémoire et chaque fonction dit sur quoi elle travaille. C’est ce qui rendra possible, dès le J03, de tenir simultanément une table d’enquête, une couche de districts et un fond de carte — et de les faire dialoguer.

Pourquoi le facteur compte. Un character est du texte libre : R n’a aucune idée des modalités possibles, et une modalité jamais observée disparaît des tableaux. Un factor porte la liste déclarée de ses modalités : un table() affichera un zéro là où il n’y a personne, au lieu de faire disparaître la ligne. Sur une région non enquêtée, la différence est celle entre « zéro observation » et « n’existe pas ».

7. Valeurs manquantes

na.rm = TRUE n’est pas un correctif, c’est une décision. Il répond « calcule sur ce que j’ai », ce qui suppose que les absences ne sont pas systématiques. Si les valeurs manquent précisément là où le phénomène est fort — un service de santé qui ne remonte pas ses chiffres parce qu’il est débordé —, la moyenne obtenue est biaisée, sans le moindre avertissement. Avant d’écrire na.rm = TRUE, il faut savoir pourquoi la donnée manque. Le J03 et le J05 y reviennent longuement.

8. Les premiers réflexes après un import — sur de vraies données

On charge un extrait réel de l’EDS-MICS Cameroun 2018 (fichier ménages), préparé pour le navigateur par _commons/data/dhs_cmr/00_extraire_dhs_pour_webr.R.

Dire de quoi on prend la moyenne. Ce fichier décrit des ménages. La taille moyenne calculée ici est donc la taille moyenne d’un ménage. Si l’on parcourait à la place un fichier de personnes, on obtiendrait un nombre nettement plus grand : un ménage de dix personnes y apparaît dix fois, un ménage d’une personne une seule fois. C’est le biais de taille — les deux chiffres sont exacts, ils répondent à deux questions différentes.

Le poids de sondage. La colonne poids_menage (HV005 au DHS, à diviser par 10⁶) existe précisément parce que l’échantillon n’est pas la population. Une moyenne non pondérée décrit l’échantillon, pas le Cameroun. Le J05 en fera la démonstration chiffrée.

9. Un premier graphique — et ce qu’il ne dit pas

Ce que la figure code. Une barre par région d’enquête ; sa longueur code le nombre moyen de personnes par ménage. L’ordre des barres est celui de la valeur, pas l’ordre alphabétique — un classement se lit d’un coup d’œil quand il est trié.

Ce que les choix techniques font. La moyenne est non pondérée : elle décrit l’échantillon interrogé, pas la population du Cameroun. Par ailleurs, la variable region est une région d’enquête, dont le découpage ne coïncide pas nécessairement avec les 10 régions administratives de la carte — le levels() du bloc précédent l’affiche. Réconcilier les deux découpages avant de cartographier est une décision de méthode, pas un problème de code ; elle doit être écrite, pas devinée.

Ce qui se lit. Un classement des régions d’enquête, et l’ordre de grandeur des écarts entre elles.

Ce qui ne se lit pas. (1) L’incertitude d’échantillonnage : aucune barre n’a d’intervalle de confiance. (2) L’hétérogénéité à l’intérieur d’une région : une moyenne de 6 peut recouvrir des ménages de 1 et de 15. (3) Où sont ces régions, et si les régions à grands ménages se touchent — un tableau trié donne un classement, il ne donne pas de voisinage. C’est exactement ce que la carte ajoutera à partir du J02.

10. Ce qui ne tourne pas dans le navigateur

Le paquet haven (import SPSS et Stata) n’est pas disponible sur repo.r-wasm.org. Le bloc ci-dessous est en lecture seule : exécutez-le sous RStudio desktop, à partir de demo_formateur_J01.qmd (section 5) ou de script_formateur_J01.R.

library(haven); library(dplyr)

# --- PIEGE DE NOMMAGE, a connaitre des le premier jour ----------------------
# DHS nomme ses variables en MINUSCULES dans les fichiers Stata (.dta) mais
# en MAJUSCULES dans les fichiers SPSS (.sav). Un test "hv001" %in% names(d)
# echoue donc SILENCIEUSEMENT sur un .sav. On resout les noms sans tenir
# compte de la casse :
noms <- names(read_sav("datasets/CMHR71FL.SAV", n_max = 0))
voulues <- c("hv001", "hv005", "hv009", "hv024", "hv025", "hv206", "hv270")
vars <- noms[match(toupper(voulues), toupper(noms))]

# col_select est indispensable : CMHR71FL.SAV pese 72 Mo et compte plus de
# 4 000 colonnes. Ne JAMAIS le lire en entier, ni lui appliquer str().
menages <- read_sav("datasets/CMHR71FL.SAV",
                    col_select = all_of(na.omit(vars)))

# haven conserve les libelles SPSS ; as_factor() les rend lisibles.
menages <- menages |>
  mutate(across(where(haven::is.labelled), haven::as_factor))

dim(menages)
table(menages$HV025)          # milieu de residence
colSums(is.na(menages))       # manquants par variable

# Le fichier femmes suit exactement le meme geste :
femmes <- read_sav("datasets/CMIR71FL.SAV",
                   col_select = all_of(c("V012", "V024", "V025", "V106", "V201")))
dim(femmes)

```{webr}
# Population 2019 (millions) de 5 regions du Cameroun

```

```{webr}
# --- Les quatre types que vous croiserez tous les jours ---------------------
# R vectorise : une operation s'applique aux 5 valeurs d'un coup, sans boucle.
num <- c(4.16, 3.11, 2.51)          # double   : une mesure
ent <- c(10L, 58L, 200L)            # integer  : un effectif
txt <- c("Centre", "Littoral")      # character: un libelle
log <- c(TRUE, FALSE, TRUE)         # logical  : une condition

sapply(list(num, ent, txt, log), class)

# Le FACTEUR : une variable categorielle, avec ses modalites declarees.
# C'est l'equivalent R d'une variable a value labels en SPSS/STATA.
milieu <- factor(c("urbain", "rural", "rural", "urbain", "rural"),
                 levels = c("urbain", "rural"))
levels(milieu)
table(milieu)          # tri a plat (equivalent tabulate)
```

## 8. Les premiers réflexes après un import — sur de vraies données

On charge un extrait réel de l'**EDS-MICS Cameroun 2018** (fichier ménages), préparé
pour le navigateur par `_commons/data/dhs_cmr/00_extraire_dhs_pour_webr.R`.

```{webr}
menages <- read.csv("_commons/data/dhs_cmr/dhs_cmr_2018_menages_extrait.csv",
                    stringsAsFactors = TRUE)

# --- Les quatre gestes a faire sur TOUT nouveau fichier ---------------------
dim(menages)                 # 1. combien de lignes, combien de colonnes ?
names(menages)               # 2. quelles colonnes EXISTENT reellement ?
head(menages, 3)             # 3. a quoi ressemble une ligne ?
str(menages[, 1:8])          # 4. de quel type est chaque colonne ?

# ATTENTION : sur un fichier EDS COMPLET (plus de 4 000 colonnes), str() et
# summary() produisent des sorties illisibles et un rendu interminable. On
# explore toujours un SOUS-ENSEMBLE de variables -- exactement comme on
# ecrirait "describe var1 var2" plutot que "describe" en STATA.
```

```{webr}
# --- Tri a plat et comptage de manquants -----------------------------------
table(menages$milieu)                    # equivalent tabulate
table(menages$milieu, menages$quintile)  # tableau croise

# Combien de NA par colonne ? Le reflexe qui evite les mauvaises surprises.
na_par_colonne <- colSums(is.na(menages))
na_par_colonne[na_par_colonne > 0]

# Combien de modalites la variable region porte-t-elle, et lesquelles ?
# On les IMPRIME plutot que de les supposer : les regions d'ENQUETE du DHS
# ne coincident pas forcement avec les regions ADMINISTRATIVES de la carte.
nlevels(menages$region)
levels(menages$region)

# Unite d'observation : UNE LIGNE = UN MENAGE (pas une personne).
# La cle est le couple (cluster_id, menage_id) : verifions qu'elle est unique.
cat("Lignes :", nrow(menages),
    "| couples (cluster, menage) distincts :",
    nrow(unique(menages[, c("cluster_id", "menage_id")])), "\n")
```
